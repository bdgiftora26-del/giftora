   377→   377→## 6. Backend architecture
   378→   378→
   379→   379→Layered, framework-light:
   380→   380→
   381→   381→```
   382→   382→src/
   383→   383→├─ app/                      # routes (thin: parse → call service → render)
   384→   384→├─ server/
   385→   385→│  ├─ services/              # business logic (catalog, cart, pricing, checkout, orders, delivery, coupons, payments, mail)
   386→   386→│  ├─ repositories/          # Prisma access only
   387→   387→│  ├─ providers/             # payment/, storage/, mailer/, captcha/ adapters
   388→   388→│  ├─ validators/            # Zod schemas shared with client
   389→   389→│  ├─ jobs/                  # cron handlers (exchange rates, abandoned carts, sitemap ping)
   390→   390→│  └─ auth.ts
   391→   391→├─ lib/                      # money.ts, slug.ts, i18n.ts, seo.ts, rate-limit.ts, logger.ts
   392→   392→├─ components/               # layout/, home/, product/, cart/, checkout/, account/, admin/, ui/
   393→   393→├─ config/site.ts
   394→   394→├─ messages/{en,bn}.json
   395→   395→├─ styles/{tokens.css,globals.css}
   396→   396→└─ tests/ (unit) + e2e/ (playwright)
   397→   397→```
   398→   398→
   399→   399→Principles: Server Components + Server Actions for mutations where natural; **Route Handlers** for webhooks and anything called by third parties. Every mutation validates with Zod, checks auth/role, is rate-limited, and writes an `OrderEvent` when it affects orders. Use transactions for order creation, stock decrement and coupon use. Errors are typed; no leaking stack traces to the client.
   400→   400→
   401→   401→### Rendering strategy
   402→   402→- Home, category, product, CMS: **ISR** (`revalidate` 300–600 s) + `revalidateTag` on admin edits.
   403→   403→- Prices depend on selected currency (cookie `currency`): render BDT base on the server and format via a small client `<Price />` that reads currency, **or** key the cache by currency — pick one and document it. Avoid layout shift.
   404→   404→- Cart, checkout, account, admin: dynamic, no cache.
   405→   405→- Search: Postgres full-text (`tsvector`) over name/description/SKU, with `pg_trgm` fallback; endpoint `/api/search?q=`.
   406→   406→
   407→   407→### API surface (Route Handlers; all JSON, Zod-validated)
   408→   408→```
   409→   409→GET  /api/products?category=&sort=&page=&city=
   410→   410→GET  /api/products/[slug]
   411→   411→GET  /api/search?q=
   412→   412→GET  /api/categories/tree?city=
   413→   413→GET  /api/currency/rates
   414→   414→POST /api/cart                    # create/get cart (cookie cartId)

   416→   416→PATCH/DELETE /api/cart/items/[id]
   417→   417→POST /api/coupons/validate
   418→   418→GET  /api/delivery/slots?date=&cityId=

   430→   430→
   431→   431→### Order & payment flow
   432→   432→1. Cart → (login/guest) → Invoice → Delivery → Payment → Complete.
   433→   433→2. `place-order` (single DB transaction): re-price items from DB, validate stock, apply coupon, compute delivery fee by city (Chittagong/Sylhet = free per `City.isFreeDelivery`; Dhaka included in product price per business rule — configurable), snapshot names/prices/rate, create `Order(AWAITING_PAYMENT)`, `Delivery`, `Payment(PENDING)`, `OrderEvent`.
   434→   434→3. Online providers: create session/intent → redirect → **webhook** marks `PAID` (idempotent by `txnRef`), decrements stock, increments `Product.orderCount`, sends confirmation mail, notifies admin.
   435→   435→4. Manual providers (bank deposit, Western Union, personal bKash): order stays `AWAITING_PAYMENT`; customer uploads proof or enters txn id; admin verifies in panel → `PAID`.
   436→   436→5. Admin moves order through `PROCESSING → OUT_FOR_DELIVERY → DELIVERED`; on `DELIVERED` admin **uploads a delivery photo** → system e-mails the sender the **Photo Confirmation** (template with photo + order summary).
   437→   437→6. Order number format `UB-{YYYY}-{6-digit seq}` (prefix from config).
   438→   438→7. Same-day/urgent: if `now > City.sameDayCutoff`, block today's date in the date picker and show a notice.
   439→   439→
   440→   440→### Security & quality
   441→   441→- Passwords: bcrypt (cost ≥12). Sessions: httpOnly, sameSite=lax, secure in prod. CSRF-safe via Auth.js + same-site actions.
   442→   442→- Rate-limit login, register, coupon validate, contact, newsletter, track-order (Redis).
   443→   443→- Never log PII/payment payloads; store gateway raw payload only in `Payment.raw` with card data excluded.
   444→   444→- File uploads: type/size allow-list, virus-scan hook placeholder, random object keys.
   445→   445→- HTML descriptions sanitized (`sanitize-html`) before saving.
   446→   446→- Security headers + CSP in `next.config.ts`.
   447→   447→- GDPR-style data export/delete for accounts (basic).
